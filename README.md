# アトリコ（画材の在庫を管理するアプリ）

**公開URL: https://shodai4.com/art-supply-manager/** （GitHub Pages / HTTPS・インストール不要・サーバー代0円）

翔大さん（絵描き・個人開発者）向けの、**サーバー代0円でそのまま実用できる画材在庫管理Webアプリ**です。
`index.html` を開くだけで動き、データは端末のブラウザ内（localStorage）だけに保存されます。PWA対応（ホーム画面に追加してオフライン起動）。

- **同じ画材を場所ごとに分けて持てる（同じJAN×フォルダで1点）**: 同じJANの画材でも、保管場所（フォルダ）が違えば別の在庫として登録・加算する。スキャンやJAN入力では**いま開いているフォルダ**（「すべて」表示なら先頭のフォルダ）の同じJANを＋1し、**別のフォルダにしか無いときは**そちらは触らずに新しい1点として登録する（「ほかのフォルダに1点」と案内する）。編集・削除・補充リスト・検索・CSVは1点ずつ（`item.id`）で扱うので混ざらない
- **同じ画材が複数の場所にあるときは「計 N点」でまとめて表示**: 同じJANの画材が**2つ以上のフォルダ**にあるときだけ、一覧で1枚の親カードにまとめる。見出しに画材名・画像・**合計数（例: `計 4点`）・何か所か（`2か所`）・星**（どれか1点でもお気に入りなら点灯。押すとその画材の点をまとめて入/切）を出し、中にフォルダごとの行を **`┣ 家  [-] 3点 [+]` / `└ アトリエ  [-] 1点 [+]`** のツリーで並べる。行からはそのまま数量の増減・詳細編集（鉛筆）・フォルダ移動（`家 ▾`＝その1点を移す）ができ、親カードの末尾に「＋ 別の場所に追加」がある。**1つのフォルダにしか無い画材・JANが空の画材はこれまでどおり1行**のままで、選択モード・買い物リストではまとめない（対象は在庫タブの「すべて」・お気に入り・メーカー別・検索結果など、複数のフォルダが混ざって並ぶ一覧）。**フォルダを1つだけ開いているとき**はまとめず、他の場所にある分を小さく「他：アトリエ 1点」と添える（`core.js` の `groupItemsAcrossFolders` / `otherPlaceSummary`）
- **「＋ 別の場所に追加」（場所を増やす）**: 編集シート（保存済みの画材を開いたとき）と、まとめカードの末尾の「＋ 別の場所に追加」から、フォルダを選んで**同じ画材情報（商品名・メーカー・ブランド・カテゴリ・色名・色番号・号数・JAN・ショップ・画像URL）を持つ新しい1点**を別のフォルダに足す（数量は1から。メモ・価格・購入ログ・お気に入り・写真は写さない＝その場所の分だけ数える）。**今の1点は動かさない**（`家 ▾` の移動とは別の操作）。選べるフォルダは縦ツリーで、**いまいるフォルダは「いまここ」、同じJANが既にあるフォルダは「登録済み」で選べない**（二重登録を防ぐ）。無料100点の上限は従来どおり新規登録のときだけ見る（`core.js` の `addItemToAnotherFolder`）
- **ファイル／メモアプリ型の在庫タブ**: 上から「フォルダ → 画材一覧」が1つの流れで並ぶ。フォルダの先頭には、削除できない固定フォルダ**「お気に入り」**が最初からある（星を付けた画材がここに入る。元のフォルダにもそのまま残る）。フォルダ（家 / アトリエ / 持ち出し用 / ストック・予備）はタイルで表示し（**お気に入りと「＋ フォルダ」を合わせた5つが1行にちょうど並ぶ5列**。アイコンの形はそのままで、余白と文字を一回り小さくしてある）、開くとヘッダー直下に大きな現在地（家アイコン › フォルダ名）と「↑」が出る。UIは絵文字なしの単色SVGのみ
- **文字をできるだけ減らしたUI**: ヘッダーは「アトリコ・合計種数・残り枠（例: `12 / 100点`）・検索（虫眼鏡）・メニュー（⋯）」の1行だけ。**下部は4つのタブバー（在庫・補充・カタログ・設定）だけ**で、絞込・並替・グリッド／リスト・複数選択・フォルダの並びは右上の「⋯」にまとめる（絞込や並びが入っていると⋯に小さな点が出る）。**役割は一目で分かる**: 「在庫」は自分の持ち物、「カタログ」はまだ持っていない画材探し（内蔵辞書の38,140件）。自分の在庫をメーカー別に見たいときは、在庫タブの上の**[ 場所ごと | メーカーごと ]** を切り替える（独立した「メーカー」タブは無くした）
- **カードから直接の在庫増減と、お気に入り**: グリッド／リストのどちらのカードにも「−」「＋」があり、編集シートを開かずに1タップで増減できる（0で「要補充」に切り替わり、0未満にはならない。＋は購入ログにも積む）。カードの下（リストは右端）の星を押すとお気に入りになり、固定フォルダ「お気に入り」に入る（もう一度押すと外れる。絞込の「お気に入り」でも絞れる）。星は写真の上に重ねず、画像を隠さない。**カードの詳細テキスト（メーカー名・色番号・カテゴリ・メモなど）は出さない**ので、商品名・「要補充」バッジ・数量だけのすっきりした並びになる。**画材の編集はカード（グリッドはタイル、リストは商品名）のタップ**で開き、編集シートの中にもお気に入りの入/切がある
- **行を左へスワイプで「削除」（iOS標準の一覧と同じ）**: 在庫のグリッドのタイル・リストの行・まとめカードの各場所行を、**左へ30px以上払うと右端から赤い「削除」**（`#dc2626`・白文字）がスッと出て止まる（右へ戻す・よそをタップ・スクロールで閉じる）。押すと編集シート・長押しメニューの削除と同じ `removeItem`（確認＋写真の削除＋再描画）を通すので、まとめカードの場所行なら**その場所の1点だけ**が消える。`−`/`＋`・星・フォルダチップ・鉛筆・「＋ 別の場所に追加」・通販ボタンの上では始めず、縦スクロール（`touch-action: pan-y`）とも競合しない。480msの長押しメニューは**横に動き始めたらタイマーを止める**ので、スワイプと長押しが二重に反応しない（スワイプ直後の1回のタップも打ち消す）。選択モード中はスワイプしない（`app.js` の `swipeRowAt` / `swipeEnd`、`styles.css` の `.swipe` / `.swipe-del`）
- **画材カードの長押しメニュー（フォルダと同じ480ms）**: 在庫のグリッド・リスト・まとめカードの各場所行を長押しすると、`−`/`＋`・星を押さずに「**保管場所を移動 / 別の場所にも追加 / 編集 / お気に入り（解除） / 削除**」を1か所にまとめて開ける（`sheetItemMenu`・`app.js` の `openItemMenu`）。フォルダの長押し（`sheetFolderMenu`）と同じ仕組みで、`LONG_PRESS_MS = 480`・指を10px以上動かしたらスクロール扱いで出さない・長押し直後の1回のタップは打ち消す（編集シートや移動シートが続けて開かない）。カードの中の `−`/`＋`・星・フォルダチップ・鉛筆・「＋ 別の場所に追加」の上ではメニューを出さず、これまでどおりのタップに任せる（選択モードのカードも同じ）。移動・追加・編集は既存のシートをそのまま使い、削除は編集シートの「削除」と同じ確認・写真の削除（`removeItem`）を通す
- **画材は4列（広い画面は5〜6列）のビジュアルグリッド**: 絵具は色名から推測した色のチューブ型アイコンを棚板に並べ、右上に在庫数バッジ。残量少なめ＝橙の枠、要補充＝赤の枠と赤字で直感的に表示（「十分」「少なめ」等の文字は出さない）
- タップで編集シート（数量ステッパー付き）。リスト表示に切り替えると1件＝2行の高密度リストで `−` `＋` の即時増減ができる
- **18カテゴリと「シリーズ」欄**: カテゴリは 油絵具・アクリル・水彩・メディウム/溶剤・筆/ナイフ・キャンバス/パネル・スケッチブック/紙・**パステル・色鉛筆・鉛筆・クレヨン・木炭/コンテ・ペン・コピック・マーカー・額縁・日本画/墨**・その他の18種類（既存8つのID・名前はそのままなので、これまで登録した画材もそのまま使える。新しいカテゴリは絞込・集計・編集シート・辞書検索のカテゴリ絞込すべてに出る）。編集シートには**「シリーズ」**欄（例: コピックスケッチ／油絵具）があり、辞書から登録すると自動で入る。辞書の3.7万件は商品名から**シリーズ／色名／色番号／号数**を分解済みで、一覧・検索タブでは「シリーズ名＋色名＋号数」の順に読める（メーカー名の二重表示もしない）。「画材名を最新にする」は商品名・メーカー・ブランド・カテゴリ・**シリーズ**・色名・色番号・号数をまとめて揃える
- 並び替え（メーカー順／新しい順／名前順／残量少ない順）＋絞込（メーカー・カテゴリ・残量）。一覧はどれも**「メーカー ＞ シリーズ」**でまとまり、この並びはまとまりの中の順になる
- 残量「残りわずか・使い切り」を自動で集める買い物リスト。**各行にはその画材のフォルダ名**（場所の色の点つきバッジ）を小さく出し、同じ画材が複数のフォルダで足りないときも「どのフォルダの分か」がすぐ分かる（在庫タブの行はこれまでどおり「フォルダ名 ▾」の移動ボタン）。**補充タブの「＋」は押した場で一覧から消さず**、買い足した数だけ在庫に足して「＋2」と数え、下の**「補充を確定」**で増やした全画材をまとめて「十分」にする（2〜3個続けて押せる。−で戻せる。確定待ちは端末に保存するので、タブを移ってもアプリを閉じても残る）
- **在庫切れはグレー表示**: 在庫0（または残量「使い切り」）のカードは落ち着いたグレーにして一目で分かるようにする。ただし ＋− の増減・タップ編集・通販リンクはそのまま操作できる（`pointer-events` は変えない）
- **通販で探す（アフィリエイト）**: 編集シートと買い物リストの「Amazon」「楽天市場」「Yahoo!」から外部サイトを開く。検索語は**JAN優先**（無ければメーカー＋商品名＋色名）。アフィリエイトIDは `shops.js` の `SHOP_AFFILIATE_CONFIG` 1か所に集約（未設定なら通常の検索URL）。設定の最下部に「Amazonのアソシエイトとして、適格販売により収入を得ています。また、本アプリの一部リンクには楽天・Yahoo!ショッピング等のアフィリエイトリンク（PR）を含みます。」を出す。Amazonアソシエイト（`shodai4-22`）・楽天アフィリエイト・Yahoo!ショッピング（バリューコマース、サイトID 3788358）を設定済み
- **登録済みの表記を最新の辞書に揃える**: 設定タブの「JAN辞書」カードにある**「画材名を最新にする」**で、JANが一致する在庫の表記（商品名・メーカー・ブランド・カテゴリ・色名・色番号・号数）を、いま使っている辞書（内蔵＋追加配信）の内容にまとめて更新する（押す前に確認を出す。ボタンの下に「※ 数量やメモは消えません」と添える）。**数量・メモ・フォルダ・お気に入り・価格・購入ログ・写真・ID・作成日は変えない**ので、古い表記のまま登録した画材も在庫を壊さずに整えられる。実際に変わった件数だけを「◯件の表記を最新辞書に揃えました」と伝え、変わるところが無ければ「すべて最新の表記です」で終わる（何度押しても安全。`core.js` の `syncItemsWithDictionary`）
- **JAN辞書の追加配信（DBゼロ）**: 同梱38,140件に加えて、`jan-extra.json` を起動時に取得して `localStorage` にキャッシュし、メモリ上の辞書へ重複なく合成。通信できないときは同梱＋キャッシュでそのまま動く。設定タブのカードは**「対応画材数：38,140件」**とカンマ付きの件数を出し（追加配信を合成した数）、辞書シートに「内蔵 38,140件 ＋ 追加配信 N件」と最終同期を表示する
- **辞書に提案**: 辞書に無いJANを入れたときだけ「辞書に提案」が出る。GitHubアカウントがあればIssue作成画面（JAN・メーカー・商品名・出典をプリフィル）、無ければ文面をコピーしてメールで送れる
- スマホのカメラでJANバーコード読取 → 内蔵辞書から商品情報を自動補完。**iOSアプリでは AVFoundation のネイティブ検出**（`plugins/art-barcode-scanner` の軽量プラグイン。画像を1コマずつJSで解析せず、端末のハードウェアが EAN-13 / EAN-8 / UPC / CODE128 をその場で認識する）で読むので速い。Web（PWA）では**同梱のhtml5-qrcode**に自動で切り替わり、WKWebViewでも動き、オフラインでも読める（CDNからコードを読まない）
- **カメラ画面が開かないときは、固まらずにアプリ内カメラへ**: iOSアプリのネイティブ読取（AVFoundation）は、**WebView を載せている画面から直接**カメラ画面を出す（別ウインドウ任せにしない）。出たかどうかを0.8秒で確かめ、出ていなければ Capacitor の `presentVC` も試し、それでも出なければ `unavailable` で JS に返す。JS 側も `native.startScan` を**5秒で打ち切る**（`scanner.js` の `withTimeout`）ので、「カメラ起動中」のまま固まらず、**同梱の html5-qrcode（アプリ内カメラ）に自動で切り替わる**（「カメラ画面を開けませんでした。アプリ内カメラで読み取ります」と添える）。自分で閉じるボタンを押したとき（`cancelled`／`stopped`）だけは静かに閉じる
- **連続スキャン（バーコードを続けて登録）**: 読取シートの「連続スキャン」をONにすると、カメラを閉じずに何本でも続けて登録できる（OFFは従来どおり1本で閉じる）。iOSアプリではカメラ画面を開いたまま待ち受けるので、1本ごとに開き直さない。読み取ると3通りに自動で振り分ける — 登録済み品は在庫を＋1（買い足しログにも積む）、内蔵辞書にある未登録品は商品名・メーカー・カテゴリ・色名・色番号・JANを辞書から入れて在庫1で登録、辞書に無いJANはメーカー名＋JANで仮登録（あとから一覧・編集で直せる）。同じJANがカメラの前に止まっていても2.8秒は数えない（連続の誤爆防止）ので、ラベルを構えたまま何本も掃くように読める。シート内に「今回の登録・加算ログ（件数・直近5件）」と「完了」ボタンがあり、無料上限（100点）に達したときは新規登録だけを止めて登録済みの＋1は続けられる（`scan-flow.js`）
- **商品画像（実物写真）**: 編集シートで手元の写真を選ぶと、長辺480px・JPEG品質0.75に自動圧縮して端末内（IndexedDB `art-supply-images`）へ保存。グリッドの棚には写真を白背景・`object-fit: contain` で見切れなく表示し、リスト左のサムネイルにも出る。写真が無い画材は従来の絵具チューブSVGのまま
- **商品画像（JANから取得／中継サーバー方式）**: `workers/rakuten-image-proxy/` の Cloudflare Workers を1つ公開し、`images.js` の `DEFAULT_IMAGE_PROXY_URL` にURLを入れておくと、**利用者は何も登録せずに**JANから商品画像URL（300x300）を取得できる（認証情報は Worker の秘密に置き、フロントには出さない）。中継サーバーは**楽天市場 商品検索API と Yahoo!ショッピング 商品検索API（v3）の併用**で、Secret が入っているほうを先に試し、メンテナンス・認証エラー・回数制限・画像なしのときはもう片方で補完する（楽天のキーが未設定なら Yahoo! が先。楽天の管理画面がメンテで止まっていても Yahoo! だけで動く）。中継サーバーが未設定・停止時のみ、設定の「楽天アプリID＋アクセスキー」で楽天APIを直接叩く上級者向けの逃げ道を使う。設置手順（Yahoo!のClient ID発行を含む）は `docs/rakuten-proxy-setup.md`。画像URLを手で貼ることも可能。表示優先順は ①手元写真（IndexedDB）→ ②画像URL → ③チューブSVG／カテゴリ別アイコン（読み込み失敗時は自動でアイコンへ）
- **画材の一覧は、どこでも「メーカー ＞ シリーズ」**: 在庫（場所ごとのフォルダ内・お気に入り／すべての画材／未分類・検索結果）・在庫の「メーカーごと」・補充・カタログ・辞書の一覧は、すべて同じ形（**メーカー見出し → シリーズ見出し → 画材**）で並ぶ。メーカーもシリーズも五十音順（カタカナ・ひらがなを混ぜても「あいうえお順」）で、見出しの右端に丸い件数バッジが出る。見出しはタップで開け閉めでき（在庫・補充は最初から開いた状態、カタログは閉じた状態から）、開閉の状態は画面ごとに覚える。**行・タイルの名前は、見出しに出ているメーカー名・シリーズ名を繰り返さない**（例: 見出し `パンパステル ＞ 油絵具` の行は `ウルトラマリン ブルー 15ml`）。スマホ幅でも見切れず、どの画面でも同じ表記になる（`core.js` の `groupItemsByMakerSeries` / `seriesItemLabel` / `createGroupOpenState`）
- **在庫タブの中の「メーカーごと」**: 在庫タブの見出しの右横にある小さなチップ **[ 場所 | メーカー ]** を押すと、持っている画材をメーカー別のまとまり（メーカー ＞ シリーズ・件数つき・五十音順）で見られる（全幅のセグメントバーは廃止し、見出しの右に置くコンパクトなチップにした）。見出しをタップで開け閉めでき、開いた中はグリッド／リストの設定に従い、星や −/＋・長押しメニュー・スワイプ削除もそのまま使える。初期表示は「場所」で、フォルダを開く操作と複数選択は「場所」に戻して行う。メーカーを見ている間はフォルダ欄とパンくずを隠し、チップはその見出しの右に残る
- **カタログタブ（内蔵JAN辞書のカタログ検索）**: 下の「カタログ」タブで、アプリ内蔵のJAN辞書（38,140件）を商品名・メーカー・JANで検索できる（自分の持ち物ではなく、まだ持っていない画材を探す場所）。並びは「メーカー（選んだときはカテゴリ・シリーズ）→検索バー→検索結果」。**スペース（半角・全角）で区切るとAND検索**（例: `ホルベイン 赤`）になり、**ひらがな・カタカナ、全角・半角、大文字・小文字のゆらぎは吸収**する（`ほるべいん` でも `ホルベイン` に当たる。NFKC＋小文字化＋カタカナ→ひらがな。索引は辞書ごとに1回だけ作る）。メーカーは224社から五十音順に選べ（カタカナ・ひらがなが混ざっても「あいうえお順」。例: ニチバン → ぺんてる → ホルベイン）、選んだメーカーの下にカテゴリ（油絵具・水彩・筆など）の絞り込みが出る。**さらに「シリーズ」のプルダウン**（`すべてのシリーズ（件数）`＋各シリーズ名・件数）でも絞れる（ホルベインのようにシリーズが多いメーカーでも画面を縦に押し潰さない）。シリーズの選択肢は**いまの検索語・メーカー・カテゴリに当てはまる商品から集計**し、メーカーやカテゴリを変えたら無くなった選択は自動で「すべて」に戻る。**検索結果はメーカー見出しごとにまとめて表示**し（見出しも五十音順）、**見出しはタップで開け閉め**できる（▶／▼）。**検索文字が空で「すべてのメーカー」のときは全メーカーの見出しを閉じた状態で並べる**ので、224社の見出しと件数が一画面で見渡せる。検索文字を入れるか、メーカーを選ぶと、該当メーカーが**自動で開く**（手で閉じることもできる）。閉じているメーカーの中身は描画しないので軽く、開いたメーカーは**先頭50件＋「もっと見る（残り◯件）」**で何千件でもたどれる（自動展開が多くのメーカーに広がるときは行数に上限を置く）。メーカーを開くと**シリーズ見出し**（五十音順・件数つき）が並び、シリーズを開くと商品行が出る（在庫・補充と同じ形）。各行は**色名・号数・容量だけ**（見出しに出ているメーカー名・シリーズ名とグレーのJANは繰り返さない）。結果の「追加」でそのまま自分の在庫に入り（すでに登録済みのJANは「登録済み」と表示）、商品名をタップすると内容を入れた登録フォームが開く。3.7万件でも軽いよう、入力は180msのデバウンスにしている（ヒット件数は全件を数えて出す）
- **オフラインで登録した画材の画像を後から補完**: オフライン中にスキャン・辞書登録すると商品画像の取得が見送られるが、**アプリ起動時とオンライン復帰時**に、JANがあり画像も手元写真も無い画材だけを、1まとまり8件・1.2秒間隔で裏側から静かに補完する（`auto-image.js`）。同じJANは1回だけ、ユーザーが設定した画像・写真は絶対に上書きしない
- **最下部のAdMobバナー（iOSアプリ）**: Capacitor ネイティブ起動時だけ画面の最下部（タブバーのさらに下）にバナーを出す。**いまは TestFlight で位置と Pro の非表示を確かめるため、`admob.js` の `USE_TEST_ADS = true` で Google 公式のテスト広告**（アプリ `ca-app-pub-3940256099942544~1458002511` / バナー `ca-app-pub-3940256099942544/2934735716`）を出す（テスト広告なのでタップしても無効トラフィックにならない。`isTesting` / `initializeForTesting` も true）。**App Store 審査提出の直前に `USE_TEST_ADS = false` へ戻す**と本番ID（アプリ `ca-app-pub-5739782559889389~2686704558` / バナー `ca-app-pub-5739782559889389/1132135646`、`scripts/configure-ios.mjs` の `ADMOB_APP_ID` も同じ値）に切り替わる。Info.plist のアプリIDはテスト中も本番のまま（テスト広告ユニットは自分のアプリIDでもテスト広告を返す）。バナーの高さはプラグインの実測値を CSS 変数 `--ad-h` に入れ、タブバー・FAB・一覧の下端・シートが隠れないよう押し上げる（Web／GitHub Pages では広告枠も余白も出さない）。`preview-375.html?ad=56` で、バナーが出ている状態の余白を確認できる
- **利用規約・プライバシー・サポートはアプリ内で読める**: iOSアプリの WKWebView は `target="_blank"` のリンクを開けないため、同梱の `terms.html` / `privacy.html` / `support.html` へのリンク（設定下部のフッターとプランカードの中）は押しても無反応だった。アプリ内ではリンクのクリックを横取りして（`links.js` の `legalDocKey`）、同梱HTMLの本文を読み物シート（`sheetLegal`）に出す（通信が無くても読める。見出しと「閉じる」は固定し、本文だけスクロールする）。同梱ページを読めないときは、公開している同じページを Safari（SFSafariViewController）で開き、それもだめならURLをコピーする。Web版はこれまでどおり別タブで開く
- **iCloud自動バックアップ（iOSアプリ）**: 同じApple IDなら、アプリを削除して入れ直しても、起動時に在庫・フォルダ・設定・お気に入りが裏で戻る（`NSUbiquitousKeyValueStore` を使う軽量プラグイン `plugins/art-icloud-sync`）。自動で戻すのは**この端末にまだデータが無いとき（初回起動）だけ**で、手元にデータがあるときは勝手に置き換えず、iCloudのほうが新しいときは設定の「iCloudから復元」で選んでもらう。全データ削除のあとはiCloud側にも空の状態を送るので、消したものが戻ってこない。写真・色見本の画像（IndexedDBのBlob）は容量が大きいのでiCloudに載せない（JSON書き出しと同じ方針）。iCloudにサインインしていない・使えないときは設定に理由を出すだけで、在庫管理はそのまま動く。これまでのJSON書き出し／読み込みも残している
- **色見本・参考写真の添付（Pro）**: 画材ごとに、チューブの残量・塗った色・ラベルなどを最大6枚まで端末内（IndexedDBの `samples`）に保存し、編集シートで追加・表示・削除できる（長辺480px・JPEG 0.75に圧縮）。画材を削除すると、その画材の写真も一緒に消える。iCloud・JSONには含めない
- **補充リストのコピー・共有（Pro）**: 補充タブの見出しの「コピー」「共有」で、いまの「要補充」を買い物メモの文面（日付・商品名・容量）にまとめてクリップボードへ、またはiOSの共有シートへ渡す（共有シートが使えないときはコピーに切り替える）
- **通販シートのYahoo!在庫・参考価格**: 「通販」を開くと、JANがある画材だけ、ページを開く前にYahoo!ショッピングの在庫を裏で調べ、「在庫あり（¥1,200〜）」「在庫なし」「確認できませんでした」を出す（中継サーバーの `/stock`。30分キャッシュ）。別JANの商品は数えない。オフライン・失敗時はリンクだけをそのまま使える
- **カタログの上部固定**: 絞り込み（メーカー・カテゴリ・シリーズ・検索）と「検索結果」の行は画面上部に残し、一覧だけを別のスクロール面にして、下の文字が透けないようにした（重ねて固定しない）
- **カタログのお気に入りメーカー**: メーカー見出しの星で登録／解除し、上部の「お気に入りメーカー（N件）」を開くと折り返しで並ぶ（ワンタップでそのメーカーに切り替え。横スクロールにしない。0件のときは行を出さない）。メーカーの一覧・プルダウンは今までどおり全部残す
- **カタログの高速化**: 起動後の空き時間にメーカー別の索引を1回だけ作り、メーカー・カテゴリ・シリーズの切り替えで3.7万件を走査しない。検索用の正規化文字列も読んだ1件だけを作る（起動時に数万件を連結しない）
- **画材費の2軸集計とCSV（Pro）**: 単価（参考価格・円）を入れると、設定タブに **今の在庫価値**（単価×在庫数。使った分だけ減る）と **記録済み合計金額**（`＋` で買い足すたびに購入ログへ積まれる。使い切った画材も残る）を並べて表示。カテゴリ別／メーカー別の棒グラフ（上位6件＋ほか）と、BOM付きUTF-8・CRLFのCSV書き出し（Excelでそのまま開ける13列）
- **無料上限とProの土台**: 無料は **100点・フォルダ3つ**（`pro.js`）。固定フォルダ「お気に入り」はフォルダ数に数えない。フォルダの枠は**あとから作った分だけ**を数え、最初からある4つの保管場所（`BASE_FOLDER_IDS`）は数えないので、無料のままでもフォルダ内にフォルダを作れる。上限は**新規登録のときだけ**判定し、100点を超えている既存データは消さず、閲覧・編集・在庫増減・削除・バックアップはそのまま使える。上限に当たると短い Pro 案内シートが出る。課金はまだ繋いでおらず、設定の「Proプレビュー」で Pro 特典（`上限なし`・`画材費とCSV`・`写真・色見本`・`買い物リスト共有`・`確定申告レポート`・`広告なし`）を試せる。**Proの間は AdMob のバナーを出さない**（`admob.js` の `adFree`）ので、特典は実際に効いているものだけを並べる（未実装の機能は並べない。StoreKit の接続点は `docs/ios-release-plan.md` §8）
- **バックアップの復元は2通り**: 「まとめる」はフォルダと画材を足し、同じIDは更新日時の新しいほうを残す（手元のデータを消さない）。「置き換える」は確認のうえ全入れ替え
- **フォルダの中にフォルダ（階層化）**: フォルダを開いた場所の「＋ フォルダ」で子フォルダを作れる（並べ替えと一覧は「⋯」→「フォルダの並び」）（`{ id, name, color, parentId }`）。フォルダを開くと上に子フォルダのチップと「＋ 子フォルダ」が並び、親を開くと子・孫の画材もまとめて表示。パンくずは `家アイコン › 家 › 机まわり › 引き出し1` のようにルートから現在地までを**枠のない文字リンク**で並べ（見出しのすぐ下）、**途中の階層をタップするとその階層へ一気に移動**できる（幅が足りないときは折り返して全階層を見せる・横スクロールで隠さない）。自分自身・配下を親にはできず（循環防止）、親を削除しても子フォルダは1つ上へ逃げて画材は移動先へ移るので破綻しない。既存データ（parentId なし）はトップ階層としてそのまま読める。**フォルダは長押し（約480ms・指を動かしたらキャンセル）で「編集／移動／削除」のメニュー**が開く（在庫タブのフォルダのタイルと「フォルダの並び」の一覧のどこからでも）。移動先の選択（フォルダの移動・画材の1件／複数選択の移動）は、**1行1フォルダの縦ツリー**（深さのインデント＋`└`）で、親・子・孫のどこでも1タップでそのまま移動できる（自分と自分の配下は選べない）
- **複数選択して一括移動**: 右上の「⋯」→「複数選択」で選択モードになり、タイル／リストをタップで選べる（左上にチェック）。下の操作バーに「N件・全選択・移動・やめる」が出て、移動先は階層つきの一覧から選ぶ。移動後は選択解除して即保存
- **ルートは「スマートフォルダ → フォルダ → 未分類」の3段**: 在庫タブのルート（家）では、上段に **「お気に入り」** と **「すべての画材」** を横2つで並べ（どちらもフォルダをまたいで集める仮想フォルダ。点数つき）、その下に自分で作ったフォルダを5列で並べる。一番下は **未分類（どのフォルダにも入っていない画材）があるときだけ** 出し、0件なら何も出さない（ルートがフォルダだけでスッキリ見える）。
- **追加・編集シートは、よく使う項目だけを上に**: 商品名・メーカー・カテゴリ・シリーズ・色名・色番号・号数/容量・在庫数・残量・保管場所・お気に入りを上に並べ、JAN・画像取得・購入店・単価・メモ・写真メモ・画像URL・通販は **「▸ もっと詳しく（購入店・メモ・写真など）」** に畳む（初期は閉じ。閉じていても保存で値は消えない。中身があるときは見出しに「JAN・写真」「3件」のように点で知らせる）。**「保存」ボタンはシートの下端に固定**し、中身だけがスクロールするので、長いフォームでもスクロールせずに保存できる（セーフエリア・キーボード・広告バナーに重ならない）。辞書から探す導線はシートから外し、カタログタブとバーコード読取にまとめた
- **バーコード読取の枠**: 同梱スキャナの `qrbox` は使わず、カメラ映像を切り取らずに（幅100%・高さは映像の縦横比）表示し、ガイド枠は箱の中央に固定する。375px/393px・iOS WKWebView でも映像と枠がズレない
- **ナイトモード（ダーク）**: 設定の「表示」で 自動（端末に合わせる）／ライト／ダーク を選べる。`localStorage`（`art-supply-manager/theme`）と設定の両方に保存し、再起動しても維持。`<html data-theme>` と `<meta name="theme-color">` が連動し、カード・シート・入力欄・検索・棒グラフ・下タブバー・在庫0のグレー表示までダーク用の配色変数で切り替える
- **お試し用サンプル（8点）**: 初回起動（まだ0件で、サンプルを入れたことがないとき）は、実在メーカーの画材8点が最初から入っている（シリーズ名も入っているので、最初から「メーカー ＞ シリーズ」の見出しが並ぶ）。油絵具・水彩・アクリル・筆・キャンバス・スケッチブック・溶剤をひととおり揃え、在庫0が2点あるのでグレー表示と通販検索（Amazon／楽天市場／Yahoo!）をすぐ試せる（値段は目安）。空の一覧と設定の「サンプル」からも入れられる。設定のボタンは、入っていなければ「サンプルを入れる」、入っていれば「サンプルを消す」（`sample-01`〜`08` だけを消し、自分で登録した画材とフォルダは残す）に切り替わり、何度でも入れ直せる（`samples.js`）。全部消しても勝手に戻らない

## 使い方（ローカル）

```bash
cd art-supply-manager
python3 -m http.server 8080      # または任意の静的サーバー
# → http://localhost:8080/ をスマホ/PCのブラウザで開く
```

カメラ読取は **https または localhost** でのみ動きます（ブラウザのセキュリティ仕様）。
`file://` で直接開いた場合も、在庫管理・フォルダ・JSON入出力・JAN手入力照合はすべて動作します（ES Modulesのため、Chrome系で `--allow-file-access-from-files` が必要な場合あり）。ローカルHTTPを推奨。

## 商品画像（実物写真）の扱い

- **手元写真**: 編集シートの「写真メモ」で選んだ画像を、`<canvas>` で長辺480px・JPEG品質0.75（1枚30〜60KB前後）に圧縮し、IndexedDB（DB名 `art-supply-images` / ストア `photos` / キーは画材ID）へBlobで保存します。localStorage（5MB）を圧迫しません。写真は端末内だけに保存され、外部へ送信されません（320pxで保存済みの古い写真もそのまま表示されます）
- **表示優先順**: ①手元写真（IndexedDB）→ ②`imageUrl`（楽天API取得または手入力）→ ③従来の絵具チューブSVG／カテゴリ別アイコン。画像の読み込みに失敗した場合は自動でアイコン表示に戻ります
- **楽天APIの設定**: 設定タブの「楽天アプリID」に、[楽天ウェブサービス](https://webservice.rakuten.co.jp/) で無料発行したアプリIDを保存してください。アプリの「許可ドメイン」に `shodai4.com`（と `shodai4.github.io`）を入れると、ブラウザから直接APIを叩けます。JANを入れて「このJANで画像を取得（楽天）」を押すと商品画像URLがセットされます（未設定・画像なし・回数制限は短いトーストで案内）
- **中継サーバー（楽天＋Yahoo!）**: 中継サーバーのURLを設定しておくと、利用者は登録なしで画像を取得できます。楽天の管理画面がメンテナンスで止まっていても Yahoo! で取得でき、画像を取得したときは「商品名（楽天／Yahoo!）」のように当たった商品と取得元が表示されます。Yahoo!のAPIを使うため、設定タブの最下部にクレジット（Webサービス by Yahoo! JAPAN）を規定のHTMLで置いています（`docs/rakuten-proxy-setup.md`）
- **バックアップ**: JSONには `imageUrl` は入りますが、手元写真は含まれません（設定画面にもその旨を表示）。バックアップを読み込んだとき、そこに無い画材の手元写真（孤児レコード）は端末内から自動で削除します

- 主な出典: e-画材.com（`www.e-gazai.com/shop/g/g<品番>/` のJANコード欄・2026-11-19に画材318件: クサカベのアキーラ・ガッシュ、額縁吊金具・ひも・トンボなどの額装金具、色紙・短冊・仮巻、色紙額）、世界堂オンラインショップ（`webshop.sekaido.co.jp` の商品ページ。JSON-LDの`gtin13`/SKU表記）、たのめーる（`tanomail.com` の商品ページ。JSON-LDの`gtin13`）、アスクル（`askul.co.jp` の商品ページの「JANコード」欄）、額のまつえだ（`matueda.com` の商品ページに明記されたJAN）、ステッドラー日本 公式（`staedtler.jp` の品番/JAN/品名表）
- 各エントリは `source`（商品ページURL）と `verifiedAt`（確認日 2026-11-17）を持ちます
- メーカープレフィックス（`JAN_PREFIXES`）は収録JANから実際に確認できた332件のみ。同一プレフィックスを複数メーカーが使う場合は `makers` に複数形で列挙しています
- 辞書は `RAW` のタプル配列 `[JAN, 商品名, メーカー, カテゴリ, 色名, 号数/容量, 色番号, 出典, シリーズ, 検索用の残り語]` で持ち、読込時にオブジェクトへ展開します（転送量削減）。商品名は商品名からメーカー名・号数の重複を落とした**整頓後の商品名**（例:「ホルベイン 油絵具 シルバー 6号」→「油絵具 シルバー 6号(20ml)」）。`keywords` には分解で落ちた語（品番など）を残し、**メーカー名・シリーズ名・商品名・色名・色番号・JAN のどれでも検索できる**ようにしています（検索の索引は空白を詰めて持つので、「ホルベイン油絵具」のように空白を入れずに打ってもヒットします）
- 世界堂のSKUには、JANではなく同店の店内コード（GS1の200〜299帯）も混在します。**先頭が2のコードは実在JANではないため収録から除外**しています（テストで固定）
- 収録対象は画材（絵具・画用液・筆・紙・キャンバス・パステル・色鉛筆・ペン/マーカー・デザイン/コミック用品・制作用具）と一般文具（ノート・ファイル・定規・カッター・はさみ・のり・消しゴム・筆記具）です。書籍（ISBN）はJANではないため除外しています
- 辞書に無いJANを読んだ場合は「このJANで新規登録」にそのまま進めます（メーカーはプレフィックスから判別、不明なら空欄）

辞書は `RAW` の配列に追記し、`JAN_PREFIXES` に事業者コードを足すだけで拡張できます。
生成元の調査スクリプトは作業ディレクトリ `tmp-jan-research/`（まつえだ・ステッドラー）、`tmp-jan2/`（世界堂）、`work/stationery-crawl/`（世界堂の全商品再巡回とたのめーる補完）にあります。

## 内蔵辞書の再分類・分解（18カテゴリ）

```bash
# すでに分解済みの辞書を読み、カテゴリだけ見直す（分解はやり直さない）
node scripts/build-dictionary.mjs

# 1.19 以前の（元の商品名が入った）辞書から、分解ごとやり直す
git show 1eeac73:jan-database.js > /tmp/jan-database-119.js
node scripts/build-dictionary.mjs --from /tmp/jan-database-119.js
```

- 商品名から **シリーズ／色名／色番号／号数／整頓後の商品名** を作り、18カテゴリへ再分類する（`scripts/lib/dict-decompose.mjs`）
- 元の商品名の語が新しい検索対象から漏れたら `keywords` に残すので、これまで検索できていた語はヒットし続ける
- `--dry-run` で集計だけ（カテゴリ別件数・変えた件数・例）を確認できる

## iPhoneアプリ化（Capacitor）

```bash
npm install
```

外部リンクは `@capacitor/browser` でSafari（SFSafariViewController）開く（`links.js`）。手元にMacが無くても、`.github/workflows/ios-build.yml`（`docs/ios-build.yml.template` と同内容）でビルドできます。必要な GitHub Secrets は `APPLE_TEAM_ID` / `APP_STORE_CONNECT_ISSUER_ID` / `APP_STORE_CONNECT_KEY_ID` / `APP_STORE_CONNECT_PRIVATE_KEY` の4つ。設計の全体は `docs/ios-release-plan.md` を参照。

## データの持ち方・拡張

`localStorage` のキーは `art-supply-manager/v1`。エクスポートJSONは
`{ app, version, exportedAt, folders[], items[], settings }` で、そのまま Supabase 等へ同期する拡張も可能な形にしています。
各アイテムは `imageUrl`（商品画像URL）、`price`（参考単価）、`purchaseLog`（買い足しの記録）を持ち、手元写真のBlobは IndexedDB `art-supply-images` にアイテムIDで保存します（JSONには含みません）。`settings` には `rakutenAppId` と `pro` / `proPreview` を保持します。
